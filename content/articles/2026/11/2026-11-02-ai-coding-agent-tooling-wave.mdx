## 一周之内，四款工具同时更新

2026 年 10 月 12 日至 16 日，Claude Code、Codex CLI、OpenCode 和 Visual Studio Code 在五天里相继发布版本更新。按行业媒体 [Shattered](https://shattered.io/claude-code-codex-cli-opencode-update-4-days-2026/) 的整理，这四波更新指向同一个方向：让编码智能体运行得更久、更独立、更可控，而不是把单条自动补全做得更聪明。

| 工具 | 版本 | 发布日期 | 核心变化 |
| --- | --- | --- | --- |
| OpenCode | 2.0 | 2026-10-12 | 从一次性 CLI 命令变为带 API/SDK 的后台服务 |
| Codex CLI | 0.163.0 | 2026-10-15 | 可在任务中途转向，只读工具并行执行 |
| Claude Code | 2.1.302 | 2026-10-16 | 分叉子代理默认开启，更易控制空闲压缩 |
| VS Code | 1.141 | 2026 年 10 月中旬 | 新增 Agents 窗口与交互式画布，引入 Agent Merge |

单看任何一条更新都不算惊艳，但把它们放在一起，能看出工具链正在为一个新的产品形态补基础设施：代理在后台运行、把工作移交给彼此、只在需要决策时打扰人类。

## Claude Code：子代理默认分叉

Anthropic 在 10 月 16 日发布的 Claude Code 2.1.302 改变了子代理的默认行为。据 [Shattered 的报道](https://shattered.io/claude-code-codex-cli-opencode-update-4-days-2026/)，分叉子代理（forked subagents）现在默认开启，父代理可以派生子代理并继承上下文，不再需要开发者每次手动接线。更新还加入了终端风格子代理行为，并让关闭空闲压缩（idle compaction）更容易——空闲压缩是后台修剪会话上下文、可能打断连续性的机制。

这三项改动针对的是同一个痛点：长时间运行的 agent 会话要么撑爆上下文窗口，要么被静默修剪导致连续性断裂。Anthropic 的选择是把两端都交给开发者直接控制。

## Codex CLI：任务中途可以转向

OpenAI 的 Codex CLI 0.163.0 于 10 月 15 日发布，解决的是另一个问题：代理开始工作后，开发者通常只有等待或取消两个选项。新版本支持在代理仍在生成响应时转向（steer），把运行方向拨到另一边而不用整轮重来；同时允许只读工具并行执行，减少文件读取或搜索串行等待的空闲时间。

对分钟级甚至小时级的代理会话来说，中途纠偏能力决定了它是否真的可用。这一更新是 OpenAI 对此的直接回应，其 [API 变更日志](https://developers.openai.com/api/docs/changelog) 记录了这类迭代的节奏。

## OpenCode：从一次性命令到后台服务

四款工具里结构变化最大的是 OpenCode 2.0。这个开源终端编码代理在 10 月 12 日发布，从"调用一次、等待一次"的命令，变成带自有 API 和 SDK 的后台服务。架构变化打开了 "Code Mode" 的大门：其他程序和脚本可以直接调用 OpenCode，而不是由人对着终端输入命令。

这是开发者工具常见的成熟路径：CLI 变成守护进程，守护进程长出 API，API 成为其他工具构建的基础。据 [Shattered](https://shattered.io/claude-code-codex-cli-opencode-update-4-days-2026/) 引用的搜索趋势数据，"open code" 的搜索量已约为一年前的 14 倍，背景代理架构的受众增长快过开源项目自身能度量的速度。

## VS Code：为多代理并行铺路

微软的 VS Code 1.141 走的是可视化路线。新增的 Agents 窗口把多个代理会话并排铺在网格里，提供交互式画布用于观察和操作运行中的代理任务。窗口内的代理可以把会话移交给另一个聊天且保持上下文，自主起草 PR 标题和描述，并汇入新的 Agent Merge 能力——协助代码审查、CI 监控、冲突解决、分支同步与合并。

这个设计选择说明微软判断的瓶颈在哪里：OpenAI 和 Anthropic 的更新大多围绕单个代理运行时的能力，VS Code 则处理开发者同时开五六个代理时如何一眼看清全局的问题。

## 沙箱成为默认：GitHub Copilot 的信号

同一时期，GitHub Copilot 的本地沙箱在 Copilot CLI、Copilot 应用和启用 Agent Host 的 VS Code 会话中全面可用（GA）。沙箱的意义在于：编码代理一旦能自己读文件、跑 shell 命令、发起网络请求，它的风险模型就和"只给人建议、等人批准"完全不同。把沙箱做成默认而非可选，等于承认代理安全是入场券而不是增值功能。

## 评估先行：微软开源 Scope

工具在往自主方向跑，怎么判断它们用得好不好成了新问题。10 月 19 日，微软在 [官方开源博客](https://opensource.microsoft.com/blog/2026/10/19/introducing-scope-open-source-evaluation-for-ai-coding-agents) 宣布开源 Scope——一个基于 Kubernetes 构建、以 MIT 许可发布的 AI 编码智能体评估平台，核心概念是 Developer Agent Experience（DevAx）：理解代理如何与你的软件交互，并用证据改进它们达成的结果。

Scope 驱动已有的编码代理（包括 GitHub Copilot、Claude Code 和带 Copilot 的 VS Code），把评估标准表示为有向无环图（DAG），用 LLM 判定代理输出是否满足标准，并保留交互轨迹和工作区快照供人工复查。它在[GitHub](https://github.com/microsoft/scope)上开放仓库，可通过 Docker Compose 快速启动本地栈。

官方博客给出了一个落地案例：Azure Cosmos DB 团队用 Scope 在五个语言的八个端到端场景中对比裸模型与 Agent Kit，评估促使 20 个 Agent Kit 问题和 27 个文档问题被修复；一次针对性的 Agent Kit 更新后，层级分区键采纳率从 47% 升到 100%，OFFSET/LIMIT 使用率从 47% 降到 0%。这些数字描述的是被评估场景内的改进，而不是对代理的通用排名。

## 工具层正在补课

Stack Overflow 的 2025 年开发者调查显示，84% 的开发者使用或计划使用 AI 工具，但明确使用 AI 代理的比例是 31%，另有 38% 不打算使用。这一差距恰好是本月这批更新想弥合的：通过让代理更易转向、更易沙箱化、更易在网格视图里监控，把代理从黑盒变成可管理的工程对象。

模型的自主能力过去两年已经足够跑多步任务，现在轮到周围的软件补课：窗口管理、CLI、沙箱、后台服务、评估平台。这个工程问题比模型发布更不显眼，但涉及状态管理、安全边界和交互设计，是基准分数无法覆盖的硬骨头。

对团队来说，工具选型正在变成周期性评估而非一次性决策——就像对待云服务那样。预算、安全审查和培训都会跟着受影响：本月 Copilot 沙箱转正，可能改变安全团队愿意放行多大范围的推广。
