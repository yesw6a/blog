## 一次例行更新，为什么值得停下来看

7 月 29 日，微软发布了 VS Code 1.131（[官方 Release Notes](https://code.visualstudio.com/updates/v1_131)）。从版本号看是常规迭代，但从内容看，它更像是 VS Code 从"代码编辑器"向"智能体工作台"转型的一次阶段性落点：agent host 架构、子智能体运行状态可视化、内置语音听写、混合 Markdown 编辑器，四个更新指向同一个方向——让人机协作的 AI 编程过程变得可观察、可介入、可编辑。

## Agent host：会话从"窗口的附属品"变成"独立进程"

1.131 的核心架构变化是 agent host：一个独立进程，专门运行 Copilot、Claude、Codex 等 agent harness，基于微软开源的 [Agent Host Protocol（AHP）](https://microsoft.github.io/agent-host-protocol/)。因为会话运行在自己的进程里，同一个会话可以同时被多个 VS Code 窗口连接和渲染。

Copilot agent 由 [Copilot SDK](https://www.npmjs.com/package/@github/copilot-sdk) 驱动，行为与 Copilot CLI、独立 GitHub Copilot 应用保持一致。开发者需要手动开启 `chat.agentHost.enabled` 并在下拉框中选择 harness。

这个变化是"地基"级别的：过去 agent 会话的生命周期绑定在编辑器窗口上，窗口一关，工作现场就没了；进程化之后，会话成为独立于 UI 的实体，可以跨窗口继续、可以被多个界面接管。官方还在逐步灰度，但它定义了后续所有 agent 功能的基础形态。

## 子智能体监控：把"黑盒"变成仪表盘

1.131 在 Agents 窗口为主对话增加了子智能体运行状态面板。当一个复杂任务被拆成多个子智能体并行执行时，不需要点开每个子智能体的对话，主界面就能直接看到三样信息：

- 该子智能体使用的模型
- 已运行时长
- 当前正在调用的工具

点击某个运行中的子智能体，会以另一个聊天打开它的完整对话，父对话保持可用。

这条更新看起来只是"加了点状态展示"，实际上是 AI 编程工具可观测性的一次补课。Agent 并行执行多任务时，最让开发者焦虑的就是不知道它在干什么、卡在哪、为什么还没结束。给每个子智能体一个"仪表盘"，是把信任成本从"盲等"降到了"随时可查"——这种透明度，是 AI 编程工具从玩具走向生产工具的必经之路。

## 内置语音听写：离线模型，音频不出设备

1.131 把语音听写做成了内置能力，不再需要安装 VS Code Speech 扩展。转录服务同时覆盖聊天输入框、文本编辑器和集成终端三个位置，三处共享同一个语音会话和麦克风设置，避免重复录音，也让口述内容准确落在目标位置。

两个工程细节值得记录：

- 转录使用私有的离线 Nemotron 模型，模型首次使用时下载，音频始终保留在设备本地；
- 开启 `dictation.experimental.llmCleanup` 后，Copilot 会在说话过程中实时润色转写文本——补上格式、去掉口头禅，但转录文本仍会发送给语言模型做清理，清理不可用时保留原始转写。

平台支持方面：Windows x64/Arm64、Apple silicon Mac、Linux x64/Arm64（glibc 2.34+）以及远程工作区可用；VS Code for the Web、Intel Mac、32 位和 Arm32 系统暂不支持。

对中文开发者来说，这一条的实际意义取决于语音识别对中文的支持程度，官方标注"更多平台和语言正在推进中"。它背后的取向更值得注意：**语音输入被当作一等输入法来设计，而不是某个扩展的附属功能**。

## 混合 Markdown 编辑器：在 agent 旁边改文件、留批注

1.131 在 agents 窗口引入了实验性的混合 Markdown 编辑器：可以直接查看 Markdown 文件、就地编辑，并在文件中添加 agent 可以执行的批注。通过 **Reopen Editor With** 可以在普通文本编辑器与这个新编辑器之间切换，agents 窗口和编辑器窗口都适用。

这个设计把"人给 agent 派活"的界面从聊天框延伸到了文件本身：不是把指令写在对话里，而是直接写在文档中，让 agent 照着文档执行。它更接近真实的团队协作方式——批注、评审、修订都发生在同一个文档上下文里。

## 其他值得记录的更新

- **终端无障碍**：屏幕阅读器用户可以按自己的节奏读完终端输出，而不影响命令继续输出；`terminal.integrated.accessibleViewPreserveCursorPosition` 设为 `always` 可保持光标位置；终端实时更新改用非打断式的 ARIA 状态通知。
- **终端尺寸浮层**：新增 `terminal.integrated.resizeDimensionsOverlay.enabled`，可以关掉调整终端大小时显示的"列 × 行"浮层。
- **Python 环境管理**：Python Environments 已全量成为 Stable 和 Insiders 的默认环境管理体验；Conda 发现延迟到需要时、并发扫描合并、Pylance 在刷新期间使用上次已知的解释器，让 Python 项目启动更快（[Python Environments 滚动说明](https://github.com/microsoft/vscode-python-environments/issues/581)）。

## 我的看法

把这四个更新放在一起看，VS Code 对 AI 编程的路线图其实很清晰：agent host 解决"会话的物理归属"，子智能体监控解决"过程的可见性"，混合 Markdown 编辑器解决"人如何介入"，语音听写解决"输入效率"。四件事合起来是一句话——**让 agent 干活的过程，从黑盒变成可以观察、可以干预、可以编辑的工作流**。

这与我观察到的行业趋势一致：编程工具的竞争焦点，正在从"模型生成代码的准不准"转向"agent 长任务运行的可控性"。谁先让开发者对 agent 的一举一动看得见、管得住，谁就更容易被接受为生产环境里的日常工具。

当然，实验性功能居多、agent host 还在灰度、中文语音支持尚未明确，是这一版留给后续迭代的悬念。对普通开发者，1.131 最实用的建议只有一条：把 Agents 窗口打开，下次派任务给子智能体时，先看看它到底在干什么。
