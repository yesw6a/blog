## 第一件事：Google DeepMind 拆了 AlphaFold 团队

据多方报道，Google DeepMind 已解散 AlphaFold 核心团队，将资源转向 Gemini 产品线。

### 为什么这件事值得单独写一段

AlphaFold 不是普通的 AI 产品。它是2024年诺贝尔化学奖成果，是真正意义上改变了结构生物学研究范式的工具。全球超过200万研究人员使用过它，从酶设计到药物靶点发现，从蛋白质相互作用到合成生物学——这条研究线索如果继续推进，下一站是**蛋白质从头设计、分子动力学模拟加速、全细胞数字孪生**。

现在，Google 说：停一下，我们先去把 Gemini 的付费用户数量冲上去。

这不只是 Google 一家的问题。它暴露的是整个 AI 行业在资本压力下的优先级排序：

| 方向 | 商业回报周期 | 社会价值 |
|------|------------|---------|
| 聊天机器人/Agent | 按季度结算 | 生产效率提升 |
| AI编程助手 | 按月订阅 | 开发效率提升 |
| 蛋白质设计/药物发现 | 5-10年 | 改变生命科学底层能力 |
| 气候模拟/能源材料 | 10年以上 | 应对人类级挑战 |

<span style="color: #e65100; font-weight: 600;">商业逻辑没有错，但商业逻辑正在系统性地把 AI 从"解决最难问题"拉向"赚最快钱"。</span>

> **我的看法：** 不是反对商业化。但一个行业如果连诺奖级别的成果都保不住，要靠"解散团队转投商业化产品"来向华尔街证明价值，那这个行业的资源配置机制一定有问题。AlphaFold 团队应该扩编三倍、预算翻倍，而不是解散。解决蛋白质折叠之后还有蛋白质设计，蛋白质设计之后还有全细胞模拟——这不是烧钱，这是下注人类知识边界。

## 第二件事：AI写的代码，越来越像债务而非资产

今天 AGI HUNT 日报里有一条被转了很多次的吐槽：一位开发者在 Codex 大型项目中，发现 AI 生成的单元测试越来越臃肿，像"看不懂的 Neuralese"，而且测试一旦失败，AI agent 从不修复——直接删掉重写。

他自己取了个词：<span style="color: #d32f2f; font-weight: 600;">测试破产（Test Bankruptcy）。</span>

### 这不是孤例

这几天类似的声音越来越多：

- **Claude Code 系统提示词膨胀到 32k tokens。** 32k tokens 是什么概念？大概是一篇中篇小说的长度。也就是说每发起一次对话，Claude Code 要先"阅读一篇小说"级别的系统指令，然后才能开始工作。成本和延迟都直接起飞。
- **MCP 工具生态过载。** 有开发者直说"删掉一半 MCP server，agent 可能立刻变聪明"。过多的工具导致上下文噪音爆炸，agent 反而找不到真正该用的那个。
- **Agent harness 的 token 效率差距高达 30 倍。** Composio 团队把 Kimi K3 放入 Claude Code、Hermes、Kimi Code 三个框架，28个任务——成功率差不多，但 token 消耗最多差了 30 倍。

<div style="border-left: 4px solid #f59e0b; background: #fffbeb; padding: 16px 20px; border-radius: 0 8px 8px 0; margin: 16px 0;">
  <p style="margin: 0; color: #92400e;"><strong>核心矛盾：</strong>AI 模型本身在变强，但我们用来包裹模型的那层"工程脚手架"——系统提示词、工具定义、agent 循环逻辑——正在以更快的速度膨胀，吃掉了模型进步带来的收益。就像发动机马力翻了一倍，但车身也重了一倍——百公里加速没变。</p>
</div>

### 工程债的三个层次

冷静拆一下，其实有三个层次在同时恶化：

**第一层：生成物的质量债。** AI 写代码快，但修改代码的能力远不如写新代码。删掉重写比修复成本低——这是 AI 的"路径依赖"。结果就是项目中堆满了 AI 写的"一次性代码"：今天能跑，明天没人能改。

**第二层：Agent 系统的复杂度债。** 为了覆盖更多场景，系统提示词越来越长，工具越来越多，记忆模块越来越复杂。但每加一个模块，系统可靠性就降一分。这不是工程师的错——是当前 Agent 架构的天然天花板。

**第三层：开发者心智的切换债。** 在 Cursor、Claude Code、Codex 之间切换时，项目上下文反复丢失。手动同步到 `CLAUDE.md` 很快过期，从 `state.vscdb` 导出又会把旧错误带进来。开发者的精力从"解决问题"变成了"管理 AI 的上下文"。

> **我的看法：** 第二层是最致命的。因为第一层和第三层的问题可以通过工具链优化来缓解，但第二层是架构性的——它直接决定了 AI Agent 的能力上限。如果解决一个真实世界的问题需要 32k tokens 的系统提示词，那说明我们还没找到正确的抽象方式。好的抽象应该是让系统越来越简单，而不是越来越臃肿。

## 三件事的交点

把这三件事拼在一起看：

1. **AlphaFold 团队解散** → AI 行业在用短期商业逻辑分配长期研究资源。速度优先，深度靠边。
2. **测试破产 + 32k 提示词** → AI 工程实践在用"堆复杂度"换"堆功能"。速度优先，质量靠边。
3. **喊刹车没人信** → 行业已经进入一种"知道跑太快会出事，但没人敢减速"的纳什均衡。

它们指向同一个问题：<span style="color: #f59e0b; font-weight: 600;">AI 行业在透支。</span>透支长期研究喂短期产品，透支工程质量喂交付速度，透支安全余量喂市场份额。
